Run it with your own key

The demo has no hosted backend. It runs on your machine, against your own fal API key, and stops at a per-session spending ceiling you choose before each run. Requires Python 3.10+, macOS or Linux, and Chrome for captured-tab control. 

git clone https://github.com/evnsnclr/realtime-diffusion.git
cd realtime-diffusion
./setup.sh

setup.sh creates the virtualenv, installs dependencies, and writes .env.local: it asks for your fal key and generates a local access code for you. The code is not a fal credential—it is a gate so nothing else running on your machine can spend your balance through localhost. It is printed when setup finishes and stored in .env.local. (Prefer manual setup? Copy .env.example to .env.local and fill in both values yourself.)

Then run ./run_demo.sh and open http://127.0.0.1:7860. Pick a source, type the access code into Local access code, select a session budget, and press Start transforming.

Streaming? Add http://127.0.0.1:7860/?stage=1 as an OBS browser source: stage mode strips the page down to the generated output on a transparent background, shows the controls only on hover (use OBS’s Interact window to drive them), and keeps a live spend-ceiling readout on the frame.

Your key never reaches the browser. The local server verifies the access code, then exchanges the key for a 120-second token scoped to this one model endpoint; the browser streams frames to fal with that token alone. An optional Apple Silicon fallback (./setup_mac.sh, ./run_mac.sh) needs no key and sends no frames off the machine.

Method

Capture is decoupled from inference: sampling continues while a request is in flight, and only the newest waiting frame is ever dispatched (latest-frame-wins). This avoids both stale lockstep capture and an unbounded cloud queue. A 48×48 luma search estimates conservative global source translation and immediately moves the last model image in the same direction; these warp updates are labeled separately from model output and are excluded from the exact-pair audit mode. 

moving source
  → sample at 10 fps
  → estimate conservative global source translation
  → retain only the newest waiting frame
  → one low-latency diffusion request at a time
  → evenly pace the interpolation pair
  → warp the latest model image between results when motion is reliable
  → generated canvas + 30 fps recording compositor
